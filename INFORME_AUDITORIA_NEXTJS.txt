4. OPORTUNIDADES DE MEJORA (NEXT.JS 16 PATTERNS)
================================================================================

A) SERVER ACTIONS (Prioridad: Media)
   Situación: Actualmente los formularios (Admin) usan el patrón tradicional 
   "Client-side Fetching" (useState + useEffect -> API Route).
   
   Recomendación: Migrar gradualmente a "Server Actions".
   - Elimina la necesidad de crear endpoints de API intermedios.
   - Permite validación y mutación directa en el servidor.
   - Compatible con el nuevo hook useActionState de React 19.

B) OPTIMIZACIÓN DE FETCHING INTERNO (Prioridad: Baja)
   Situación: Las funciones de servidor (lib/data) hacen peticiones HTTP a 
   localhost:3001.
   
   Recomendación: En funciones que corren exclusivamente en el servidor, llamar 
   directamente a la base de datos (Prisma) evita el overhead de la red local.

C) REACT COMPILER (Prioridad: Baja/Experimental)
   Situación: No activado explícitamente.
   
   Recomendación: Activar "experimental: { reactCompiler: true }" en next.config.js 
   para que Next.js optimice automáticamente los re-renderizados sin necesidad 
   de usar useMemo/useCallback manualmente.
